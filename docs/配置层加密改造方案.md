# CameraMonitor 配置层加密改造方案

| 项目 | 内容 |
|---|---|
| 日期 | 2026-08-26 |
| 状态 | 待评审（本文档只出方案，未动任何代码） |
| 决策约束 | 不引入数据库（已定）；配置界面合并为「高级设置」单一入口 + 双 Tab（已定） |

---

## 1. 现状问题

`config.ini` 目前存在以下问题：

| # | 问题 | 影响 |
|---|---|---|
| 1 | `SourceUrl` 整串内嵌摄像头账号密码（`rtsp://admin:***@192.168.0.x:554/...`） | 密码明文落盘，文件被拷贝/备份/误发即泄露 |
| 2 | `[ZLMediaKit] Secret` 明文 | ZLM 管理密钥泄露后可任意操作流媒体服务器 |
| 3 | `ConfigManager.Load` 中 `for i <= 6` 写死 | 加第 7 路必须改代码重新编译 |
| 4 | `SourceUrl` 整串存储，无法拆分字段 | 无法区分主/子码流，上云按需推流、100 路方案都受制于此 |
| 5 | 无配置界面 | 现场改配置只能手改 ini，易出错 |
| 6 | Camera04/05/06 三路同 IP（192.168.0.5） | 疑似历史配置错误，至今未核对 |

## 2. 方案选型结论

**JSON 文件做"文件版配置表" + Windows DPAPI 加密敏感字段。**

| 依赖 | 状态 |
|---|---|
| JSON 读写（`System.Web.Extensions` / `JavaScriptSerializer`） | 已引入（ZlmJson.cs 在用），零新增 |
| DPAPI（`System.Security.Cryptography.ProtectedData`） | .NET Framework 自带（System.Security.dll），仅 csproj 加引用 |

不引入数据库、不引入 NuGet 包。

## 3. 目标架构

```
┌─────────────────────────────────────────────────┐
│ config.ini（系统配置 · 瘦身）                     │
│   [ZLMediaKit] Host / RtspPort / HttpPort        │
│   [ZLMediaKit] SecretEnc  ← DPAPI 密文（替代明文 Secret）│
│   [Display]  Left / Top / VideoHeight            │
├─────────────────────────────────────────────────┤
│ cameras.json（摄像头台账 · 新文件）               │
│   动态列表：名称 / IP / 端口 / 账号              │
│   密码列 passwordEnc ← DPAPI 密文                │
│   码流通道 / 启用标志 / 排序                      │
├─────────────────────────────────────────────────┤
│ Windows DPAPI（CurrentUser 作用域）               │
│   密钥绑定「当前 Windows 账户 + 本机」            │
└─────────────────────────────────────────────────┘
        ↓ 启动时解密（仅内存中短暂存在明文）
┌─────────────────────────────────────────────────┐
│ 运行时内存                                        │
│   CameraConfig.Password（明文，不可避免）        │
│   SourceUrl 由字段拼装（不再是存储字段）           │
└─────────────────────────────────────────────────┘
```

## 4. 详细设计

### 4.1 cameras.json 结构

```json
{
  "version": 1,
  "cameras": [
    {
      "id": 1,
      "name": "Camera 01",
      "streamId": "camera001",
      "ip": "192.168.0.2",
      "port": 554,
      "username": "admin",
      "passwordEnc": "AQAAANCMnd8BFdERjHoAwE...（DPAPI 密文 Base64）",
      "channel": "101",
      "enabled": true,
      "sortOrder": 1
    }
  ]
}
```

字段说明：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | int | 摄像头唯一编号（与海康 SDK 登录会话对应） |
| `name` | string | 显示名（状态条 / 日志） |
| `streamId` | string | ZLM 代理流 ID，保持现状命名 `camera00x` |
| `ip` / `port` | string / int | 摄像头地址（从 SourceUrl 拆出） |
| `username` | string | 登录账号 |
| `passwordEnc` | string | **DPAPI 加密后的 Base64**，文件中永不出现明文 |
| `channel` | string | 码流通道：`101` 主码流；预留 `102` 子码流（上云 / 100 路方案直接启用） |
| `enabled` | bool | 停用位（预留，第一阶段默认 true） |
| `sortOrder` | int | 显示顺序 |

### 4.2 config.ini 瘦身后

```ini
[ZLMediaKit]
Host=192.168.0.136
RtspPort=554
HttpPort=80
SecretEnc=AQAAANCMnd8BFdERjHoAwE...（DPAPI 密文）

[Display]
Left=0
Top=1080
VideoHeight=540
```

- `[Camera01] ~ [Camera06]` 整段废弃（首次迁移后从 ini 中移除）。
- 兼容读取：若存在旧明文 `Secret` 字段则继续可用，同时日志提示"存在明文 Secret，建议迁移"。

### 4.3 CameraConfig 内存模型变化

| 成员 | 现状 | 改后 |
|---|---|---|
| `SourceUrl` | 存储字段，从 ini 读 | **计算属性**：由 ip/port/username/password/channel 拼装 |
| `Ip` / `Port` / `Username` / `Password` / `Channel` | 无 | 新增，从 json 读入（Password 启动时解密） |
| `Name` / `StreamId` | 有 | 不变 |

调用方（MainForm / ZlmStreamGuard / ZLMediaKitService）**不需要任何改动**——它们继续读 `camera.SourceUrl`，感知不到后面是拼出来的。

### 4.4 DPAPI 加密细节

| 项 | 设计 | 理由 |
|---|---|---|
| API | `ProtectedData.Protect / Unprotect` | .NET Framework 内置 |
| 作用域 | `DataProtectionScope.CurrentUser` | 只有加密时的同一 Windows 账户能解密，安全性最高 |
| 存储格式 | `byte[]` → Base64 字符串 | 直接放 json 字段 |
| 编码 | UTF-8 | 支持中文密码（虽然罕见） |

**CurrentUser 作用域的约束**：加密时用的 Windows 账户必须与运行程序的账户一致。工控机开机自启若是固定账户（现状如此），无影响。若现场将来需要"任意账户可运行"，改 `LocalMachine` 作用域（本机任意账户可解，安全性略降，配置改一个枚举值即可）。

### 4.5 URL 拼装与转义（现状隐藏 bug 顺带修）

现状整串存 URL，密码若含 `@ : / #` 等字符会直接破坏 URL 结构（手改 ini 时极易踩坑）。字段化后拼装时对 username / password 做 URL 编码（`Uri.EscapeDataString`），特殊字符密码从此合法。

### 4.6 密文生成方式（配置窗体内完成，无命令行）

密文的生成与维护**全部在「高级设置」窗体内完成**（见第 6 节）：用户在界面输明文密码 → 点保存 → 程序内部 DPAPI 加密 → 写 cameras.json。用户全程不接触密文、不碰文件、不跑命令行。

`CameraMonitor.exe --encrypt` 命令行工具**降级为可选运维后门**（脚本批量初始化场景用），现场日常不依赖。

## 5. 迁移设计

### 5.1 首次启动自动迁移

```
启动
 ├─ cameras.json 存在？
 │    ├─ 是 → 直接加载（新路径）
 │    └─ 否 → 检测旧 config.ini 是否含 [Camera01..06]
 │              ├─ 是 → 自动迁移：
 │              │        1. 解析旧 SourceUrl → 拆出 ip/port/username/明文密码
 │              │        2. 拆不出来的整段报错并中止（提示人工处理）
 │              │        3. 密码 → DPAPI 加密 → 写 cameras.json
 │              │        4. 同 IP 多路检测：Camera04/05/06 同为 192.168.0.5 → 迁移成功但弹警告
 │              │        5. 旧 ini 改名 config.legacy.bak（不删，可回滚）
 │              │        6. ZLM Secret → SecretEnc 写回新 ini
 │              └─ 否 → 报错退出（无任何配置可用）
```

### 5.2 回滚

保留 `config.legacy.bak`；删除 cameras.json 并恢复 bak 即回到旧版行为（前提：代码保留旧 ini 读取分支，作为迁移源保留一个版本周期）。

## 6. 配置界面设计（高级设置窗体）

### 6.1 入口

右键菜单（现状唯一的交互方式）**只加一项**：

```
2#主溜井        ✓     ← 现有
3#主溜井              ← 现有
──────────────
高级设置…             ← 新增（唯一入口）
──────────────
关闭                  ← 现有
```

- 点击「高级设置」→ 弹出配置窗体（`Form.ShowDialog()`，标准带边框窗口，**弹在主屏**可拖动，不干扰副屏视频墙）。
- 可选（待拍板）：加操作口令。若加，点菜单项先弹口令框，只拦这一处入口。

### 6.2 窗体结构：TabControl + 两个 TabPage

| Tab | 内容 | 操作 |
|---|---|---|
| **摄像头管理** | DataGridView 摄像头台账（名称/IP/通道/账号/密码/启用）；同 IP 多路黄色警告条 | 新增 / 编辑 / 删除 / 测试连接 |
| **ZLM 设置** | ZLM 主机、HTTP 端口、RTSP 端口、Secret（掩码显示，可切换明文）、测试 ZLM 连接 | 表单编辑 |

- 底部共用按钮栏：**保存 / 取消**——一次保存统一落盘（cameras.json + config.ini），不是两个 Tab 各自保存。
- 扩展性：将来加「显示设置」「日志」直接加 TabPage，右键菜单不变。

### 6.3 关键交互

| 时机 | 行为 |
|---|---|
| 首次启动（无 cameras.json 且无旧 ini 可迁移） | 自动弹出「高级设置」，引导录入第一遍 |
| 表单中密码列 | 永远显示 `••••••`；编辑时输明文，仅内存中存在 |
| 点「测试连接」（单路） | 临时调 ZLM 建代理 → 验证拉流 → 返回成功/失败，不落盘 |
| 点「保存」 | 校验 → DPAPI 加密 → 写 cameras.json + config.ini → **自动重载 6 路流（不重启程序）** |
| 同 IP 多路（如 Camera04/05/06 → 192.168.0.5） | 列表标红 + 警告条 + 保存时再确认 |
| 取消 / 点 ✕ | 不落任何盘，直接关闭 |

### 6.4 保存后热重载边界

热重载范围：摄像头配置变化 → 删除旧 ZLM 代理 → 按新配置重建代理 → 重启对应 VLC 播放器。
ZLM 主机/端口变化 → 全量重建（相当于自动恢复流程复用）。
本阶段不做：改配置时保持画面不闪（重载期间该路会短暂黑屏 2~4s，属可接受）。

## 8. 约束与风险

| # | 风险 | 等级 | 对策 |
|---|---|---|---|
| 1 | DPAPI 密文绑定「账户+机器」：换工控机 / 换 Windows 账户 / 系统重装后密文失效 | 中 | 失效表现为解密抛异常 → 明确报错"密码密文在本机无效，请重新录入"；运维流程：新机器上跑一次迁移重新加密 |
| 2 | 与 6 路无感切换的耦合：`_slotCameraIndexes` 固定 0~5 | 中 | 加载后校验数量：**不足 6 路 → 启动失败并提示**；超过 6 路 → 取前 6（分页属 100 路方案，本方案不引入） |
| 3 | 运行时内存存在明文密码 | 低 | 不可避免；进程不落地，防护边界是"文件不泄露明文"，不是"防管理员" |
| 4 | Ghost 系统镜像部署的机器密文失效 | 低 | 同风险 1 对策 |
| 5 | vshost 调试进程残留导致 json 写入失败 | 低 | 迁移写在启动最早期，失败即中止并提示（沿用现有 vshost 排障经验） |
| 6 | 明文密码从内存进入 VLC/ZLM 日志 | 低 | 现有日志脱敏（Regex.Replace 打码）已覆盖 rtsp 密码与 secret，保持不变 |

**明确不防护的场景**：能登录该工控机的管理员（可 dump 进程内存拿明文）。本方案防护的是**配置文件流出机器**（备份、远程支援发文件、装机拷贝）这一类场景。
